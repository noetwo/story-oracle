# 故事神谕·二创版（Story Oracle Fork）

基于 [故事神谕（Story Oracle）](https://github.com/namelessone88/story-oracle) 1.89.0 的二创版本，原作者 namelessone88。

1.x 是只保留普通聊天和剧情参谋的「精简版」；2.0 起把其余模式加了回来，功能与原版基本一致：

- 💬 **普通聊天**：在独立窗口里就当前剧情提问，不碰主聊天。
- 🩺 **诊断**：修 MVU 状态变量（含自动诊断、🎛 变量编辑器、修改器、检查存档）。
- 📖 **世界书**：聊世界书，或让它直接帮你改世界书（含 🪄 智能选条）。
- 🧭 **剧情参谋**：和参谋一起构思剧情走向，采用后悄悄引导主聊天。支持单拍方案和多拍的序列引导。
- ✨ **校正**：修最新回复的「AI 味」（手动、✂️ 选段、自动、📋 自定义模板）。
- 🎭 **角色工坊**：聊几句就把一个角色打磨成完整设定，写进人设或世界书 NPC 条目。

相对原版的改动：

1. **所有提示词都能在设置里改。** 每个模式实际发给模型的每一段文字（共 114 条），都可以逐条修改、一键恢复默认，不用再改代码。
2. **序列引导的「贯穿设定」。** 给一整条序列写下幕后的既定事实，每一拍都会带着它注入主聊天，叙事模型就不会自己编出相互矛盾的解释。
3. **主聊天注入精简成一段「剧情导向」**，只在主聊天正文生成时挂上；引导可以暂停。
4. **连接存档与模型切换栏**：输入框上方一键切换模型；存档改动后可直接保存回去。快捷回复栏里有「故事神谕」按钮。

## 和原版的关系

- **没有的功能**：弧线（透明 / 盲盒）、落拍感应、下一拍建议、数据库联动、插件接口（StoryOracleAPI，大纲版等插件依赖它）、更新检查。
- **共用数据**：二创版和原版用同一套设置和聊天数据，所以原版里的连接配置、补全预设挑选、各模式的讨论记录、诊断精选条目、校正配置与套餐、自定义模板、工坊草稿、已采用的方案 / 序列，装上二创版后都还在。原版里改过的诊断 / 世界书 / 轻校 / 精校 / 校正目标提示词，会直接出现在「提示词」页里、标为已自定义。
- **不能同时启用**：两者界面元素一样，同时启用会冲突。二创版检测到原版在运行时，会弹出提示并停止加载。请在扩展管理里只启用其中一个。
- **切回原版**：二创版新写的数据（新登记的那些提示词、贯穿设定）原版会直接忽略。另外，原版的弧线优先级高于序列和单拍，所以二创版每次全新采用方案或序列时，会顺手清掉这个聊天里原版留下的弧线数据，免得切回原版后旧弧线压过你的引导。

## 安装

1. 在酒馆「扩展 → 安装扩展」里填 `https://github.com/noetwo/story-oracle`，安装后文件夹名是 `story-oracle`。也可以下载后把这几个文件放进 `data/<用户名>/extensions/` 下任意名字的文件夹。
   - 原版「故事神谕」也叫 `story-oracle`：装过原版的话，先在扩展管理里删掉原版（数据不会丢，见上一节「共用数据」），再按网址安装。
2. 在「扩展 → 管理扩展」里只启用一个「故事神谕」（原版和二创版不能同时启用），刷新页面。
3. 以后在扩展管理里点「更新」即可拿到新版本。

## 使用

### 普通聊天

点输入框上方快捷回复栏里的「故事神谕」按钮（或魔杖菜单里的 🌙）打开窗口，直接提问。窗口读取角色卡、世界书、最近的对话记录和 MVU 变量（可在设置里调整），回答只留在神谕窗口里。

### 诊断 · 世界书 · 校正 · 角色工坊

用法与原版 1.89.0 相同：标题栏的 🩺（诊断）、📖（世界书）、✨（校正）切换模式，🎭 角色工坊在 ⋯ 菜单里（开了「工具移到标题栏」时直接在标题栏）。每个模式上方有自己的设置栏；后台自动诊断在「诊断设置」里勾「自动诊断每条新回复」开启，自动校正在「校正设置」里切到「去 AI 味」再勾「每条新回复自动去 AI 味」。各功能的详细说明见原版 README。

每个模式的讨论记录独立保存，切模式不会混在一起；只有普通聊天和参谋两房可以导出 / 导入对话。

二创版在校正上多了两样：

- **手动校正的「只改此标签内的正文」**：正文包在某个标签里（比如 `<Interleaving>正文</Interleaving>`）时，填上 `Interleaving`，模型就只看到、只改这一段，标签外的构建块、状态栏、占位符原样保留。自动去 AI 味本来就有同样的设置，在「进阶设置 → 只校正此标签内的正文」（会自动识别，识别不对再手填）。
- **校正目标「古风词混入（仅西幻 / 现代设定）」**：把混进西幻 / 现代卡里的公子、作揖、银两、时辰、江湖这类中式古风词，换成本设定的说法；穿越者、系统这类外来者的对白、内心和他们带来的能力法宝不动。手动校正可以直接点模型右边的 ⚡「杀古风」，一步改完。和「魔法被写成理科」一样按卡勾选；勾了「带上角色卡」或「带上激活世界书」时，会优先用卡里真实存在的称谓、货币和机构名。

两种校正都能带上前文：手动是「加载前文条数」，自动是「进阶设置 → 上下文」，填 -1 = 全部。被 /hide 隐藏的楼层默认不带（设置「上下文」页开了「读取隐藏楼层」才带）。

### 剧情参谋

点标题栏的 🧭 进入参谋模式，和参谋讨论剧情走向。

- **单拍方案**：参谋给出 1~3 个 `<StoryPlan>` 方案卡，点「开始引导」后，主聊天会被悄悄推向这个方向。
- **序列引导**：讨论的是一整段长线剧情时，参谋会排成一条 `<StorySequence>` 序列。采用后同一时间只有当前这一拍在引导主聊天，演完点「完成」换下一拍，换拍不花钱。
- 方案条上的 ✏️ 可以手改这一拍的内容（目标 / 切入 / 节奏），强度档可以随时切换。
- 一拍演完了没有由你自己判断，点「完成」换下一拍。
- 想先跑偏一阵再回来，点方案条上的「暂停」，主聊天就暂时不注入；点「继续」接着引导。

### 注入了什么

引导进行中，主聊天每次生成只多出一段，贴在玩家消息里（很多中转会把对话中间的 system 消息挪到最顶上，贴进玩家消息才稳）。只有主聊天的正文生成（发送、重新生成、换一条、继续）会带上它，其它插件的后台请求不会：

```
<剧情导向>
以下是{{user}}希望接下来的剧情走向，供你构思正文时参考：贯穿设定是整条剧情的背景与走向，眼下只推进当前这一拍，不要提前演后面的阶段；请用你自己的叙述自然地写出来，不要照抄、复述或提及这段内容。
【贯穿设定】
（总体走向 + 幕后事实）
【第 3/8 拍：拍标题】
目标：……
切入：……
节奏：……
</剧情导向>
```

单个方案没有贯穿设定和拍号，那两部分自动省略。外壳和「这一拍的内容」都在设置的「提示词 → 主聊天注入」里，可以改。

### 贯穿设定

多拍序列最常见的问题：某一拍只透露了一半真相，主聊天模型不知道后面的设定，就会自己编一个解释。比如你设定的是「家族实权在妻子手里，丈夫身体健康，只是推到台前的傀儡」，第三拍透露了「掌控人是妻子」，模型却写成了「丈夫卧病在床」。

贯穿设定就是用来解决这个问题的：

- 参谋输出序列时，会在 `title` 下面写一段 `canon:`，内容是讨论中定下来的隐藏真相（人物真实身份与状态、隐藏关系、谜底）。
- 序列卡上可以在采用前补写或修改；采用后，方案条拍列表的第一行「📌 贯穿设定」可以随时查看和编辑。
- 每一拍注入主聊天时，贯穿设定都在「剧情导向」里、这一拍的前面。你用 ✏️ 手改某一拍，也不会把它弄丢。
- 回参谋房修改序列时，参谋也看得到它；新提案里带了 `canon:` 就整段替换，不带就沿用原来的。
- 设定每一拍都会注入，太长会占用上下文。超过 1500 字时会提示，但不会截断。

### 切换模型

输入框上方有一条小栏，显示当前用的是哪个连接存档、哪个模型。点它会列出你存过的连接存档，点一下就切换，不用进设置；最下面的「管理连接…」直接打开设置的「连接」页。

连接存档在 设置 →「连接」页管理：填好端点、密钥、模型后起个名字点「存为新存档」。高级选项（经酒馆后端转发、地址原样使用、附加参数）和生成参数（温度、最大 tokens、流式输出、发送温度参数）也存在存档里，切到哪个存档就用哪个存档的设置；改了这些同样会显示「已修改」，点「保存到此存档」写回去。存档平时只占一行，显示当前在用的那个；点开列出全部存档，点哪个就用哪个，每行末尾可以删除。

### 设置

点 ⋯ → 设置打开，设置会铺满整个窗口，右上角 ✕ 回到聊天。顶部分成 5 页：

- **连接**：连接存档、连接方式（直连 / 酒馆连接配置文件）、端点和模型、生成参数。跨域转发、原样地址、附加参数收在「高级选项」里。
- **上下文**：读多少条对话记录、是否带角色卡和变量状态、记忆扩展、世界书范围。
- **人格**：说话人格与自定义人格。
- **提示词**：见下一节。
- **界面**：窗口配色、快捷回复栏的「故事神谕」按钮、聊天栏 🌙 按钮等。

### 修改提示词

在设置的「提示词」页，先点分组（普通聊天、诊断、世界书、剧情参谋、主聊天注入、校正、校正目标、角色工坊、角色锻造、上下文段落、人格、内置破限），再点条目。每条都写着这段文字什么时候发、给谁看；点开后在下方编辑。

- 改过的条目和分组都会标出来，点「↺ 恢复默认」回到内置版本。没改过的条目以后会跟着扩展更新自动改进。
- 带变量的条目，编辑区下面列出能用的变量，点一下就插入到光标处。写法是 `{%变量名%}`：
  - 一行里的变量都为空时，这一行会整行省略（比如「切入：{%seed%}」，没有切入点就不出现这一行）；
  - `{%#变量名%}…{%/变量名%}` 只在变量非空时保留中间这段，`{%^变量名%}…{%/变量名%}` 反之。
  - `{{user}}` 等酒馆宏照常可用。
- 有些条目包含程序要解析的格式（比如 `<StorySequence>`、`<UpdateVariable>`、`<LorebookEdit>`、`<FixedReply>`、`<CharDraft>` 的格式说明）。删掉了必需的变量或格式字样时，提示行会标红并写明缺了什么。
- 角色锻造的工序里，每个「■ 部分名」小节会按「草稿包含」的勾选删留，改写时请保留这些小节头。
- 校正目标：没改过时，第二段只在所需依据（角色卡 / 前文 / 世界书）在场时附加；改过后整份恒发。精校的「DeepSeek / Gemini 侧重」改过、「Opus 侧重」没改时，Opus 侧重也用改过的那份（与原版一致）。
- 诊断里「…段」这类数据段按原样发送，不展开 `{{user}}` 等宏；世界书模式整体都不展开宏（条目要逐字对上锚点）。
- 数据的排版（世界书条目清单、校正信封里的 `<characters>` 等标签、补丁回执）不在这里：它们和提示词里的格式说明一一对应，改了反而对不上。
- 「主聊天注入」组的改动会马上应用到正在进行的引导上；已经用 ✏️ 手改过的拍和方案，仍然用你手改的那份。

### 保留的集成

MVU 变量读写、柏宝书 / 小白X 记忆桥、柚月记忆兼容、其它扩展的世界信息、世界书 EJS 渲染与「自定义」范围、补全预设挑选、内置破限、自定义人格、连接存档、对话导入导出、模板广场与分享，都与原版一致。
